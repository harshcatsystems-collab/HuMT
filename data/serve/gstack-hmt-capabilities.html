The Core Insight

GStack is not a collection of tools. It's a process encoded as skills. The skills run in sprint order:

Think → Plan → Build → Review → Test → Ship → Reflect

Each skill feeds into the next. /office-hours writes a design doc that /plan-ceo-review reads. Nothing falls through because every step knows what came before.

The Two Core Philosophies

1. Boil the Lake

"AI makes completeness near-free. When the complete implementation costs minutes more than the shortcut — do the complete thing. Every time."


Lake = boilable (100% coverage, all edge cases)
Ocean = not boilable (multi-quarter migration)

2. Search Before Building

Three layers of knowledge:

  • Layer 1: Tried and true — don't reinvent
  • Layer 2: New and popular — scrutinize
  • Layer 3: First principles — prize above all

The Six Forcing Questions (Startup Mode)
# Question What It Tests
1 Demand Reality: "What's the strongest evidence someone would be upset if this disappeared tomorrow?" Real vs hypothetical demand
2 Status Quo: "What are users doing right now to solve this — even badly?" Current pain / workaround
3 Desperate Specificity: "Name the actual human. What gets them promoted? Fired?" Specific vs category thinking
4 Narrowest Wedge: "What's the smallest version someone would pay for this week?" Scope discipline
5 Observation: "Have you watched someone use this without helping? What surprised you?" User reality vs founder assumption
6 Future-Fit: "In 3 years, does your product become more essential or less?" Vision vs rising tide

Anti-Sycophancy Rules (Explicit in SKILL.md)

Never say during diagnostic:

  • "That's an interesting approach" — take a position instead
  • "There are many ways to think about this" — pick one
  • "You might want to consider..." — say "This is wrong because..."
  • "That could work" — say whether it WILL work based on evidence

HMT-Stack v1 — Ready for Review

These skills are extracted from documented patterns — not imagined. Each cites specific sources.

/hmt-problem-check
Based on: "problem-love > solution-love" (Ashoka Podcast)
Questions:
1. Is this solving a real problem or hypothetical?
2. Who feels this pain daily? Name them.
3. What's the current workaround, and what does it cost?
4. If we do nothing, what happens?
5. Are we in love with the problem or the solution?
/hmt-root-cause
Based on: "generalizes incidents into rules" (Feb 16, 19, 27)
Process:
1. State the symptom
2. Ask "Why?" 5 times
3. Distinguish: patch or system fix?
4. What rule prevents recurrence?

Anti-patterns: "We'll be more careful" ← Not a fix
/hmt-are-you-sure
Based on: "are you sure?" pattern (10+ occurrences)
Protocol:
1. State the claim
2. What evidence supports this?
3. What would disprove this?
4. Have you tested, or assuming?

Output: Verified / Likely / Uncertain / Unverified
/hmt-10-star
Based on: "identity company, not entertainment" framing
Questions:
1. What's the 10-star version hiding inside this?
2. What would make this remarkable, not acceptable?
3. Does this validate identity or just deliver utility?
